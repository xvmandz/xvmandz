# Push, PWA, звуки и TURN — PingUp 2.0

Инструкция настройки сервисов. База приложения теперь PostgreSQL; миграция описана в UPGRADE.md. Реальную доставку Push и WebRTC между сетями нужно проверить на ваших устройствах.

## 1. VAPID и очередь Push

В существующем config.local.php сохраните TURN и остальные секреты. Добавьте/проверьте:

```php
'app_origin' => 'https://app.pingup.cc',
'secure_cookies' => true,
'vapid_subject' => 'mailto:YOUR_REAL_CONTACT_EMAIL',
```

Ключи создайте **один раз** от пользователя PHP:

```bash
sudo -u www-data php bin/vapid.php
```

Команда создаёт `storage/vapid.json` с правами 0600 и не печатает ключи. Этот файл находится вне public/. Не публикуйте его и не вращайте ключи при каждом релизе: смена публичного ключа требует повторной подписки устройств. Можно задать `vapid_file` на иной приватный путь.

```bash
sudo cp deploy/pingup-push.service /etc/systemd/system/pingup-push.service
sudo systemctl daemon-reload
sudo systemctl enable --now pingup-push
sudo systemctl restart pingup-push
sudo systemctl status pingup-push
journalctl -u pingup-push -n 30
```

В unit проверьте путь проекта/PHP и пользователя. Если storage перенесён, измените ReadWritePaths. Worker использует один процесс, партии до 20 заданий, lease, timeout сети 8 секунд, четыре попытки с backoff, приоритет звонков, уникальные задания на событие/устройство и удаление 404/410 подписок. PHP-FPM записывает только очередь, не ждёт сети Push. Разрешите исходящий HTTPS к браузерным Push-провайдерам. Домены разрешены в push_hosts; неизвестный провайдер требует явного добавления доверенного домена, не `*`.

В приложении: Настройки → Звуки и уведомления → Включить системные уведомления. Разрешение запрашивается только после нажатия. Подписка каждого устройства привязана к аккаунту и версии сессии, продлевается при использовании. После суток без продления требуется снова открыть приложение; выход/смена пароля прекращают доступ к соответствующим подпискам. На одном аккаунте поддерживается до 10 устройств.

В Push отправляются только идентификаторы. Service Worker запрашивает содержимое с действующей cookie-сессией и повторно проверяет участие в чате, приватность, прочтение и DND. При недействительной сессии приватные уведомления не показываются. Доставка сторонним Push-сервисом может повториться при сбое между отправкой и записью результата; Service Worker подавляет повтор по событию в IndexedDB.

## 2. Nginx и PWA

DocumentRoot остаётся `/var/www/pingup/public`. Настройте HTTPS на app.pingup.cc. Добавьте в HTTPS server block перед общим правилом статических файлов:

```nginx
location = /sw.js {
    add_header Cache-Control "no-store" always;
    add_header Service-Worker-Allowed "/" always;
}
location = /manifest.webmanifest {
    default_type application/manifest+json;
    add_header Cache-Control "no-cache" always;
}
```

Для размещения в подпапке адаптируйте location и Service-Worker-Allowed к подпапке. Manifest использует относительные scope/start_url; config app_url должен соответствовать подпапке.

```bash
sudo nginx -t
sudo systemctl reload nginx
```

Откройте Chrome Android → Настройки PingUp → Установить приложение; если автоматический prompt недоступен, используйте меню Chrome → Установить приложение / Добавить на главный экран. После установки запуск standalone без адресной строки. PWA кэширует только явно перечисленную статику; API, сообщения, токены, сессии, вложения и аватары в Cache Storage не попадают. При отсутствии сети во время первого открытия показывается офлайн-экран; неподтверждённый пользовательский ввод сохраняется отдельно в приватной IndexedDB-очереди своего аккаунта и восстанавливается после повторного входа/перезагрузки. Ответы API, токены и байты файлов туда не записываются. После возврата сети приложение повторяет отправку с тем же client_id без дублей. Подтверждённые записи удаляются; явный выход очищает очередь своего аккаунта. Отзыв доступа к чату не позволяет отправить восстановленное сообщение. Вложения для очереди должны предварительно успешно загрузиться на сервер: выбор нового файла полностью офлайн не поддерживается. Если браузер блокирует IndexedDB или пользователь очищает данные сайта, очередь не гарантирует сохранность; приложение сообщает о сбое сохранения при отсутствии сети.

При релизе изменяйте VERSION в sw.js и версии ссылок index.php. Новая версия устанавливается в ожидании; пользователь получает кнопку «Обновить PingUp». Обновление откладывается во время звонка. Не очищайте браузерные данные для обычного обновления. Перезапустите PHP-FPM, если OPcache не проверяет изменения файлов автоматически.

Ежедневно запускайте `php bin/cleanup.php` от пользователя PHP. Настройки сохраняются в PostgreSQL: звуки, громкость, DND, системные уведомления, приватность текста, масштаб; приглушение — отдельно для каждого чата. Масштаб применяется к rem-компонентам, мобильный интерфейс имеет самостоятельные размеры.

## 3. TURN, Google Cloud и проверка обрыва звука

Сохраните действующие TURN credentials в config.local.php. Для turn.pingup.cc:3478 обычно задают UDP и TCP URLs с вашими действующими username/credential. STUN: stun:stun.l.google.com:19302. Не копируйте секреты в public/ или репозиторий.

Если Coturn размещён за внешним IP Google Cloud, задайте external-ip=PUBLIC_IP/PRIVATE_IP, listening-port=3478, realm=turn.pingup.cc, lt-cred-mech, fingerprint. Установите min-port=49160 и max-port=49200 (или свой диапазон). Разрешите входящие UDP/TCP 3478 и UDP 49160–49200 **как в Google Cloud VPC Firewall, так и в firewall ОС**, только для VM с Coturn. Пример (подставьте свой network; не запускается автоматически):

```bash
gcloud compute firewall-rules create pingup-turn --network=YOUR_NETWORK \
  --direction=INGRESS --action=ALLOW \
  --rules=tcp:3478,udp:3478,udp:49160-49200 \
  --target-tags=pingup-turn
```

Назначьте target-tag VM с Coturn. Если TLS TURN настроен, отдельно разрешите TCP 5349 и используйте turns: с корректным сертификатом. Корпоративные сети могут требовать TLS TURN на 443: это отдельная конфигурация, не смена порта без TLS. Внешний IP и DNS должны соответствовать VM. Старт Coturn не доказывает наличие ретрансляции: проверьте `turnutils_uclient` и браузерный selected candidate pair типа relay.

Клиент теперь агрегирует аудио/видеотреки в один поток, буферизует кандидаты до SDP, поддерживает версии согласования и два ICE restart, не закрывает звонок при одном отвергнутом кандидате или кратковременном сбое polling. Сервер закрепляет принятый звонок за одной вкладкой. Входящие уведомления не захватывают микрофон до ответа.

Для диагностики выполните в консоли браузера `localStorage.setItem('pingup.callDiagnostics','true')`. `PingUpCalls.getDiagnostics()` возвращает ограниченный журнал состояний и типов ошибок; `await PingUpCalls.getStats()` — счётчики RTP без IP, SDP, кандидатов, имён, текста или ключей TURN. Флаг можно удалить после проверки. На двух физических устройствах в разных сетях проверяйте звук минимум две минуты, Android background/foreground и relay. Локальный тест не заменяет эту проверку.

## Ограничения и приёмка

- Chrome/Android могут задерживать Push; force-stop браузера, энергосбережение и ограничения ОС влияют на доставку.
- Web Push способен показать входящий звонок при закрытом приложении, но не способен автоматически включить микрофон, воспроизвести собственный рингтон в закрытом PWA или гарантировать полноценный звонок в фоне. Кнопка ответа открывает приложение; пользователь подтверждает ответ на его экране.
- При открытых вкладках собственный рингтон требует ранее выполненного действия пользователя. Android управляет звуком системных уведомлений отдельно от громкости PingUp.
- Notification actions и requireInteraction поддерживаются браузерами неодинаково. Safari/iOS требует поддерживаемой версии и установки на главный экран; не проверено на реальном iOS.
- Service Worker может не показывать уведомление после истечения сессии/прочтения/DND. Некоторые браузеры в таком случае показывают своё общее уведомление о фоновом обновлении (userVisibleOnly); приватный текст в нём отсутствует.
- E2EE и password reset не входят в эту версию. Офлайн-очередь хранит только неподтверждённые отправки; история всех чатов офлайн не кэшируется.

До открытия тестерам выполните checklist: реальные Push с двумя устройствами, открытой/свёрнутой/закрытой PWA; отключение DND/превью и отдельного чата; logout и смена пароля; установка и обновление Chrome Android; два устройства в разных сетях для звонка; пробуждение приложения; ввод при клавиатуре Android. Подробный автоматический отчёт — TEST-RESULTS.md.

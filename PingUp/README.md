# PingUp 2.0.0-beta.1

Мессенджер на PHP 8.2+, PostgreSQL 15+, HTML/CSS и JavaScript без клиентского фреймворка и сборки. Проверен PostgreSQL 17.11. Новая версия не открывает SQLite в runtime; она нужна только как источник импорта из PingUp 1.1. Три локализации: украинская, русская и английская. Тёмная/светлая/системная тема, мобильная навигация, PWA, Web Push, оригинальные звуки и настройки приватности сохранены.

## Что добавлено

- Плавные переходы страниц, чатов, модальных окон и карточек; анимации сообщений, доставки, реакций и удаления. Существующие DOM-строки и медиаплееры не пересоздаются при polling. Отключение анимаций в настройках и поддержка prefers-reduced-motion.
- Одна обновляемая запись о каждом аудио/видеозвонке в личке: направление, состояние, результат, длительность от принятия до завершения и повторный звонок. История старых звонков переносится при импорте. Это метаданные, не аудиозапись разговора.
- Удаление только у себя на устройствах аккаунта и удаление у всех. В личке участник может удалить входящее сообщение у всех; в группе/канале чужое сообщение удаляет владелец или серверный администратор. Право требует участия в переписке. Удаление уже скачанных файлов с чужих устройств невозможно.
- Собственные каналы PingUp: название, описание, изображение, публичное @имя, поиск, подписка, приватные приглашения с заменой ссылки, управление подписчиками. Читателю показан отдельный интерфейс без composer. Публикует владелец; серверный администратор сохраняет прежнее право модерации. Это каналы внутри PingUp, без интеграции Telegram API.
- PostgreSQL identity/RETURNING, транзакции и точечные advisory locks, конкурентная выдача Push-заданий SKIP LOCKED, индексы для истории/дельт/доступа к файлам и триграммного поиска. Обработка сообщений и списка чатов пакетная, без N+1. Неизменённый polling не пересылает последние 100 сообщений; курсор change_seq доставляет изменения, включая старые сообщения и личное удаление. Уведомления читателям создаются одним SQL fanout; внешний Push остаётся в worker.

## Запуск

Нужны PHP CLI/FPM с pdo_pgsql, fileinfo, mbstring, curl, openssl, session и json; PostgreSQL с pg_trgm. Для однократного импорта нужна pdo_sqlite. Для криптографии Push рекомендованы GMP или BCMath. Node.js нужен только разработчику для браузерных тестов.

1. Создайте БД и пользователя PostgreSQL. Заполните `config.local.php` по примеру либо задайте PINGUP_DATABASE_DSN / PINGUP_DATABASE_USER / PINGUP_DATABASE_PASSWORD. Пароли храните вне public/ и репозитория.
2. Сохраняйте приватные storage/uploads, storage/sessions и VAPID-ключи вне DocumentRoot.
3. Подготовленный vendor включён в архив; альтернативно `composer install --no-dev --prefer-dist --optimize-autoloader`.
4. Выполните `php bin/migrate.php`, затем `php bin/doctor.php`. Создайте администратора командой `php bin/create-admin.php --username=admin --name='PingUp Admin'`; пароль вводится через stdin.
5. Для локальной проверки: `PINGUP_SECURE_COOKIES=0 php -S 127.0.0.1:8080 -t public`. На продакшене используйте HTTPS + Nginx + PHP-FPM и secure cookies.

Полные команды, перенос данных, резервные копии, worker, обновление PWA и откат: [UPGRADE.md](UPGRADE.md). Настройка Push, звуков и TURN: [NOTIFICATIONS-CALLS.md](NOTIFICATIONS-CALLS.md).

Проверки и измерения: [TEST-RESULTS.md](TEST-RESULTS.md). Изменённые файлы: [CHANGED-FILES.md](CHANGED-FILES.md).

Версия остаётся beta. Настоящая доставка внешнего Push, физический Android, WebRTC между разными сетями и Coturn на сервере владельца требуют приёмки. Google Cloud VM/app.pingup.cc автоматически не обновлялись. Масштабирование до инфраструктуры Telegram не заявляется: синхронизация пока polling, файлы и PHP-сессии используют приватное файловое хранилище, список чатов ограничен 200, участники в интерфейсе показаны до 100. Для нескольких веб-узлов потребуется общее хранилище сессий/медиа и отдельная работа с realtime, очередями и нагрузкой.

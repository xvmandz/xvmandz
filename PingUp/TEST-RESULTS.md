# Проверка PingUp 2.0.0-beta.1 — 8 октября 2026

Проверки выполнялись на отдельном **настоящем PostgreSQL 17.11**, PHP 8.4.24 с PDO PostgreSQL и Chromium/Playwright. SQL PostgreSQL выполнялся сервером PostgreSQL, не SQLite-эмуляцией. Зависимости Composer прежние, разрешены для PHP 8.2.0. PHP 8.3/FPM, PostgreSQL 15/16, Google Cloud и физический Android здесь не запускались. Production app.pingup.cc не менялся.

Все тестовые базы названы pingup_test_*, аккаунты случайные, пароли существуют только в памяти. Пользовательские базы/ключи/настройки не входят в архив.

## Пройдено

- **11/11 HTTP integration.py**, без пропусков: регистрация/приглашение/CSRF/сессии, настоящая CLI-роль admin и verified, профили/темы/локали, лички/группы, идемпотентность отправки, ответы/реакции/прочтение, доступ к чужим чатам, пересылка/избранное, файлы/Range/права, typing/поиск/закрепы, права публикации каналов. Дополнительно: шестой обычный пользователь блокируется, администратор не расходует квоту; смена пароля отзывает другую сессию.
- **browser-smoke.cjs**: UI-вход, оптимистическая отправка, сохранение старых DOM-строк и composer при polling, входящие сообщения, инертный HTML сообщения, светлая тема, UK/RU/EN, мобильный переход назад.
- **update-browser.cjs**: удаление только у себя синхронизируется между двумя вкладками; другой аккаунт сохраняет сообщение. Удаление входящего у всех удаляет DOM-строку у отправителя. Нет пересоздания соседней строки. Начало/принятие/завершение и повторное завершение звонка через API дают одну карточку. Неизменённый polling возвращает пустые массивы сообщений. Создание канала через UI, описание/публичное имя, поиск без учёта регистра, подписка через UI, readonly-компоновка читателя, запрет чужой публикации/редактирования, изменение описания владельцем, приватный deep-link, замена приглашения, выход и запрет чтения после выхода. Настройка анимаций сохраняется; prefers-reduced-motion учитывается; мобильная ширина проверена. WebRTC-медиа в этом сценарии не устанавливается.
- **notifications.php**: PostgreSQL-схема, Push-авторизация/приватность/прочтение/DND/mentions, несколько устройств, дедупликация события/задания, разные lease, endpoint-проверка/SSRF, удаление expired endpoint без потери другого, реальное VAPID/aes128gcm библиотеки с Mock HTTP 201, владение звонком одной вкладкой, несколько SDP-ревизий, одна запись звонка в чате, personal-hide не удаляет чужую копию и не показывается в Push, дельта скрытия и пустой повторный polling.
- **import-postgresql.py**: отдельная SQLite schema 3 импортирована в пустую PostgreSQL schema 4. ID/пароль-хеш/роли/аватар с циклическим FK/переписка/участники/настройки/прочтение/ответы/реакции/вложения сохранены. Старый звонок получает одну запись и верную длительность. Новые identity-ID выше перенесённых. Исходный SQLite-файл побайтно не изменился. Повторный импорт в заполненную цель запрещён. После добавления блокировок импорт проверен повторно на свежей базе.
- **concurrency.py**: два независимых PHP-процесса и две PostgreSQL-сессии одновременно отправляют одинаковый client_id — одна запись сообщения и уведомления. Два конкурирующих вызова общему получателю — один звонок, второй call_busy. Это проверка гонок, не распределённый нагрузочный тест.
- **experience-browser.cjs**: приватность/дедупликация уведомлений, отсутствие уведомления активного чата, сохранение масштаба, 1366×768 / 1920×1080 / 2560×1440 / 3840×2160 / 820×1180 / 390×844, настройки/профиль/поиск и четыре масштаба, уменьшенный клавиатурой viewport, статический SW-кэш, офлайн-экран и восстановление.
- **outbox-browser.cjs**: офлайн-сообщение сохраняется после перезагрузки и доставляется однажды после восстановления сети; replay client_id не создаёт дубль; явный logout очищает личную IndexedDB-очередь.
- **pwa-browser.cjs**: SW вызывает оригинальный showNotification при неактивной вкладке; instrumentation фиксирует приватность/дедупликацию. Проверены закрытие после прочтения, статический кэш и офлайн-восстановление с авторизованной сессией. Это проверка браузерного API, не внешней доставки или настоящего Android.
- **pwa-update.cjs**: реальный SW update в отдельной копии статики, waiting-кнопка, блокировка активации при имитированном состоянии звонка, ручная активация, удаление старого кэша и сохранение сессии. Повторно пройден после изменения установки статики на cache:reload.
- PHP/JS-синтаксис, совпадение **631 ключа** и плейсхолдеров трёх локалей, наличие ассетов, финальная целостность ZIP и SHA256SUMS.

При адаптации найден лишний message_id в сериализованной реакции; формат API исправлен, итоговый HTTP-прогон зелёный. Новые сценарии также выявили ошибку heartbeat чужой вкладки: раньше сервер отказывал всему calls.poll, и вкладка могла не получать финальный статус. Теперь чужая/завершённая вкладка получает статус без обновления heartbeat. Проверка сохранения настройки после reload сначала ожидала настройку на главном экране; тест исправлен, чтобы открыть настройки после reload. Тесты регистрируют новые аккаунты: при повторных запусках защита частоты регистраций остаётся активной; используйте новую базу, не отключайте защиту в коде.

## Измерение производительности

`tests/performance.php`: одна локальная база, **100 чатов / 5 000 сообщений**, после ANALYZE:

| Операция | SQL-запросы | Время одного прогона |
|---|---:|---:|
| Список 100 чатов с участниками, хвостом, реакциями и unread | 6 | 15,23 мс |
| Нормализация 50 текстовых сообщений | 2 | 0,85 мс |
| Неизменённый sync: 0 строк сообщений/обновлений | — | 19,75 мс |

Количество запросов проверяется тестом; время — измерение этой среды, без SLA. Вложения/ответы/звонки добавляют ограниченное число пакетных запросов. Не измерялись десятки тысяч одновременных клиентов, удалённая БД, балансировщик, медиатрафик или сравнение с Telegram. Браузер не перерисовывает неизменённые строки, read не отправляется заново с тем же курсором, typing DOM не обновляется при том же составе людей. Эти изменения уменьшают лишнюю работу; они не отменяют polling.

## Не подтверждено

- Стабильность настоящего WebRTC-аудио/видео, первоначальная проблема «полсекунды и обрыв», два устройства в разных сетях и Coturn. Managed Chromium имеет WebRtcIPHandling=disable_non_proxied_udp; политика не менялась и не обходилась. Здесь подтверждены серверные состояния/история/сигнализация, не медиа.
- Внешняя Push-доставка через FCM/Mozilla/Apple/Windows и системный показ на настоящем Android. Криптография, очередь и браузерный API проверяются отдельно; это не внешний end-to-end тест.
- Реальная установка и фоновые ограничения Android, Nginx/PHP-FPM/systemd на VM владельца, production firewall/TURN, масштаб распределённого кластера и high-load SLA.

## Повторение

Только отдельная PostgreSQL-база. Перед каждым CLI-тестом, которому нужна пустая база, создавайте новую `pingup_test_*` и задавайте PINGUP_DATABASE_DSN / USER / PASSWORD приватно. Тесты не принимают production DB по имени. PINGUP_STORAGE_PATH — временный приватный каталог; `php bin/migrate.php` создаёт схему. Для import-postgresql.py дополнительно pdo_sqlite; PHP выбирается PINGUP_TEST_PHP. Для browser-тестов нужен отдельно установленный Playwright, PINGUP_TEST_URL указывает loopback. Подготовленный vendor нужен для notifications.php.

```bash
php tests/notifications.php
python tests/import-postgresql.py
python tests/concurrency.py
php tests/performance.php
python tests/integration.py --base-url http://127.0.0.1:8080
node tests/browser-smoke.cjs --base-url http://127.0.0.1:8080 --browser-executable /usr/bin/chromium
PINGUP_TEST_URL=http://127.0.0.1:8080/ node tests/update-browser.cjs
PINGUP_TEST_URL=http://127.0.0.1:8080/ node tests/experience-browser.cjs
PINGUP_TEST_URL=http://127.0.0.1:8080/ node tests/outbox-browser.cjs
PINGUP_PHP_BINARY=/usr/bin/php node tests/pwa-update.cjs
```

Для полного HTTP-прогона CLI-admin создаётся в отдельной базе, тестовые реквизиты передаются только через PINGUP_TEST_ADMIN_USER / PASSWORD. Browser-тестам ставьте PINGUP_MAX_USERS=0 на отдельном сервере; HTTP-тест квоты проверяется с PINGUP_MAX_USERS=5. Не запускайте сценарии с созданием аккаунтов на app.pingup.cc.

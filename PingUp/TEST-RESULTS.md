# Проверка PingUp 2.1.0 — 8 октября 2026

Среда проверки: **PHP 8.3.6 CLI** (встроенный сервер `php -S`, не PHP-FPM), **PostgreSQL 16.15** (целевая версия 17 здесь не запускалась; используются только возможности, доступные с PostgreSQL 15), Chromium из Playwright 1.64, Node.js 22. Nginx, PHP-FPM, systemd, физические Android/iOS-устройства, реальный SMTP-провайдер и внешние Push-сервисы не запускались.

Все тестовые базы называются `pingup_test_*`, создаются заново перед каждым набором; аккаунты случайные, пароли существуют только в памяти теста. Пользовательские данные, ключи и настройки в архив не входят.

## Что проверяют новые тесты

- **integration_21.py** (HTTP, реальный сервер и PostgreSQL):
  1. Контакты: запрос, принятие, отклонение с паузой 7 дней, отмена, удаление; приватность профиля/фото/последнего визита для не-контактов.
  2. Блокировки на сервере: сообщения, звонки, запросы в контакты, профиль, поиск.
  3. «Кто пишет первым» и «кто звонит»: все / контакты / никто.
  4. Курсоры доставки и прочтения; «отчёты о прочтении: никто» с взаимностью.
  5. Глобальный поиск: минимальная длина, только префикс @username / начало слова, скрытие из поиска, отсутствие e-mail, лимит частоты, каналы и открытые группы.
  6. Premium: выдача администратором на срок и бессрочно, продление от текущей даты окончания, отзыв, история, журнал аудита, запрет для обычных пользователей, gating тем.
  7. Загрузки: лимит 50 МБ / 200 МБ Premium, проверка сигнатуры по расширению, отказ HTML/SVG/исполняемых, загрузка частями, отмена.
  8. Центр обратной связи: создание с вложением, ответы, статусы, внутренние заметки не видны пользователю, вложения доступны только владельцу и администраторам, лимиты, уведомления.
  9. E-mail: привязка кодом через локальный SMTP-приёмник, неверные попытки, вход по подтверждённому e-mail, восстановление пароля без раскрытия существования аккаунта.
  10. Каналы: оформление/пресеты, роли и права администраторов, блокировки, приглашения с лимитом и сроком, журнал, передача владения с паролем, архив, удаление, статистика.
  11. Сообщения: опросы, отложенные сообщения, альбомы, стикеры, комментарии и просмотры, избранное, массовое удаление, пересылка, несколько закреплённых, реакции с лимитом.

Проверены сохранность сообщений и реакций, роли владельцев каналов/групп, курсор доставки из курсора прочтения, время закрепления, стандартный набор стикеров, работа списка чатов и отправки после обновления, продолжение identity-последовательностей.

## Измерение производительности

`tests/performance.php`: одна локальная база, **100 чатов / 5 000 сообщений**:

| Операция | SQL-запросы | Время одного прогона |
|---|---:|---:|
| Список 100 чатов (участники, последнее сообщение, реакции, непрочитанные, приватность, статусы доставки/прочтения, Premium) | 14 (лимит теста ≤ 16) | 27,08 мс |
| Нормализация 50 текстовых сообщений | 3 (лимит ≤ 5) | 1,28 мс |
| Неизменённый sync: 0 строк | — | 22,85 мс |

Рост числа запросов по сравнению с 2.0 (6 → 14) — пакетные запросы приватности, контактов, блокировок, Premium и курсоров; число не зависит от количества чатов. Время — измерение этой среды, не SLA.

## Найдено и исправлено во время проверки

- `ESCAPE '\\'` в LIKE давал HY093 в PDO PHP 8.3 → условие удалено (по умолчанию PostgreSQL использует `\`).
- Права участника: `+` не переопределял ключи → `array_replace`.
- Комментарий к публикации сдвигал курсор прочтения ленты канала → курсор двигают только обычные сообщения.
- Владелец архивированного канала мог публиковать → публикация запрещена.
- Неудачная попытка ввода e-mail-кода откатывалась вместе с ошибкой → счётчик фиксируется до ответа.
- Рассинхронизация истории браузера при одновременном закрытии панели и открытии подстраницы → отложенный `pushState`.
- Сдвиг поля ввода из-за `scrollIntoView` → собственная прокрутка контейнера, `overflow: clip`, высота `100dvh`.

## Не подтверждено

- Реальные Android/iOS-устройства, экранная клавиатура, жесты на физическом сенсоре, установка PWA — проверено только эмуляцией Chromium.
- Отправка писем через настоящий SMTP-провайдер (SPF/DKIM/доставляемость) — проверена только с локальным приёмником.
- Внешняя доставка Web Push через FCM/Mozilla/Apple; WebRTC между разными сетями и через Coturn (calls-browser работает в loopback).
- PostgreSQL 17 и PHP-FPM/Nginx на сервере владельца; нагрузка множества одновременных клиентов.
- Онлайн-оплата Premium не реализована.
- Раздел 15.11 технического задания (ограничение размера текста обращения) получен обрезанным; на сервере описание и ответы ограничены 5000 символами, но значения из задания неизвестны.

## Повторение

Только отдельная PostgreSQL-база `pingup_test_*`; production-базы тесты отвергают по имени. Перед каждым CLI-тестом, которому нужна пустая база, создавайте новую и задавайте `PINGUP_DATABASE_DSN` / `PINGUP_DATABASE_USER` / `PINGUP_DATABASE_PASSWORD` и временный `PINGUP_STORAGE_PATH`. `upgrade-postgresql.php` требует **пустую** базу (сам ставит схему 4); остальным — `php bin/migrate.php`.

```bash
php bin/migrate.php
php tests/notifications.php
php tests/performance.php
php tests/upgrade-postgresql.php          # на пустой базе
python3 tests/concurrency.py
python3 tests/import-postgresql.py
PINGUP_MAX_USERS=5 PINGUP_TEST_ADMIN_USER=... PINGUP_TEST_ADMIN_PASSWORD=... \
  python3 tests/integration.py --base-url http://127.0.0.1:8080
PINGUP_TEST_SMTP_PORT=2525 PINGUP_TEST_ADMIN_USER=... PINGUP_TEST_ADMIN_PASSWORD=... \
  python3 tests/integration_21.py --base-url http://127.0.0.1:8080
export NODE_PATH=/path/to/node_modules PINGUP_BROWSER_EXECUTABLE=/path/to/chromium PINGUP_TEST_URL=http://127.0.0.1:8080/
node tests/browser-smoke.cjs --base-url http://127.0.0.1:8080 --browser-executable "$PINGUP_BROWSER_EXECUTABLE"
node tests/update-browser.cjs
node tests/messenger21-browser.cjs
node tests/experience-browser.cjs
node tests/outbox-browser.cjs
node tests/pwa-browser.cjs
node tests/sounds-browser.cjs
node tests/calls-browser.cjs
PINGUP_PHP_BINARY=/usr/bin/php node tests/pwa-update.cjs
```

Для `integration_21.py` сервер запускается с `PINGUP_SMTP_HOST=127.0.0.1 PINGUP_SMTP_PORT=$PINGUP_TEST_SMTP_PORT PINGUP_SMTP_SECURE=none PINGUP_MAIL_FROM=no-reply@pingup.test` и теми же переменными базы (тест сам поднимает приёмник и запускает `bin/mail-worker.php --once`). Администратор создаётся `bin/create-admin.php` в тестовой базе. Browser-тестам ставьте `PINGUP_MAX_USERS=0` на отдельном сервере. Не запускайте сценарии с созданием аккаунтов на production.
